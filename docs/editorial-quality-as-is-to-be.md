## 1. 목표

모두일보의 기사 신뢰도·독창성·포털 대응 수준을 10점 만점 8.5점으로 끌어올리고,
이를 개인의 감각이 아니라 발행 시스템으로 반복 재현한다.

- 신규 기사 100점 환산 이동평균 85점 이상
- 개별 기사 80점 미만 출고 금지
- 직접취재·자체분석·공개자료 검증·광고·외부제공을 사실대로 구분
- 기사마다 원문, 검증 행위, 추가 가치, 시각물 출처, AI 역할을 감사 가능하게 기록
- 독자에게는 취재·검증 근거를 공개하되 AI 역할과 혼동시키지 않음

이 점수는 네이버·구글의 비공개 알고리즘 점수를 예측하지 않는다. 검색·뉴스 제휴 심사에서
설명 가능한 편집 품질 증거를 내부 기준으로 만든 것이다. 8.5 달성이 제휴나 노출을 보장하지 않는다.

취재·제작 축과 AI 역할 축은 분리한다.

- 취재·제작: direct / desk / sponsored / wire

AI를 활용한 인터뷰 기사도 직접취재일 수 있다. 사람이 썼더라도 보도자료만 재구성한 기사는
desk다. 이 분리가 네이버 대응보다 먼저 지켜야 할 편집 신뢰의 핵심이다.

## 5. 편성 전환

- 12카테고리×2편을 의무량으로 운영하지 않는다. 검증 가능한 기사만 내고 최대 24편으로 둔다.
- 매주 최소 편성: 인터뷰 3편, 기관 질의 3편, 현장 1편, 자체 데이터 분석 2편,
  원문·문서 비교 5편. 나머지는 공개자료 검증 기사로 채우되 80점을 통과해야 한다.
- 직접 답변을 받지 못한 질의는 contactStatus: no-response로 기록하고 desk 기사로 출고하거나 HOLD한다.
- 기사의 차별점은 요약이 아니라 원문 간 충돌, 신청 함정, 계산 방법, 당사자 답변,
  현장 관찰, 사후 결과 중 하나 이상이어야 한다.

## 6. 시행·검증

- npm run report:editorial — 점수·목표 현황
- npm run check:editorial — 2026-09-01 이후 80점 미달 시 실패
- npm run test:editorial — 정상·누락·허위 인터뷰 차단 회귀 테스트
- npm run report:reporting — direct/desk 및 취재 방식 구성
- npm run content — 동일한 품질 게이트를 거쳐 생성
- npm run build — 사이트 최종 검증

기사 화면에는 verificationNote가 있는 경우 취재·검증 정보를 표시한다. AI 역할은 내부
감사값으로 유지하고, 전 기사 공통 AI 활용 고지는 별도로 유지한다. 일반 기사는 배포 전
책임 기자의 실명·검수시각·reporterInsight를 요구하고, 해설은 사실 본문과 분리해 공개한다.
