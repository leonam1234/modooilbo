# 결정 기록 (Decisions)

> **이 폴더는 "무엇을 골랐는가"가 아니라 "왜 그것이었고 다른 것은 왜 아니었는가"를 남깁니다.**

## 왜 필요한가

코드는 결과만 보여 줍니다. 커밋 메시지는 근거를 담을 수 있지만 **나중에 찾아 읽기 어렵습니다** —
6주 뒤에 "홈 히어로가 왜 이렇게 돼 있지?" 하고 묻는 사람이 `git log` 를 뒤지지는 않습니다.

근거가 사라지면 두 가지가 일어납니다.

1. **이미 검토하고 버린 안을 다시 꺼냅니다.** 같은 조사를 두 번 합니다.
2. **의도한 제약을 버그로 오해해 "고칩니다".** 예컨대 홈 리드에서 사업 축을 빼는 건
   의도인데, 모르는 사람 눈에는 누락으로 보입니다.

## 언제 쓰는가

**되돌리기 어렵거나, 대안이 여럿이었거나, 나중에 "왜 이렇게 했지?" 소리가 나올 일**이면 씁니다.

| 쓴다 | 안 쓴다 |
|---|---|
| 매체 정체성·노출 구조 변경 | 오타·문구 수정 |
| 기자 배정·발행 규약 변경 | 라이브러리 버전 올림 |
| 여러 안을 비교해 하나를 고름 | 명백한 버그 수정 |
| 법·고지 관련 판단 | 리팩터링(동작 동일) |
| 의도적으로 **안 한** 결정 | |

마지막 항목이 특히 중요합니다. "하지 않기로 했다"는 기록이 없으면 다음 사람이 그걸 합니다.

## 어떻게 쓰는가

**작업을 시작할 때 문서를 만들고, 진행하면서 채웁니다.** 끝나고 몰아 쓰지 않습니다 —
그러면 결론에 맞춰 근거를 지어내게 됩니다.

파일명: `NNNN-짧은-제목.md` (번호는 순번, 재사용 금지)

문서는 작업과 함께 자랍니다.

```
작업 전   배경 · 근거 데이터 · 선택지와 트레이드오프   ← 여기까지가 설계서
결정 시   고른 안과 이유 · 버린 안과 이유
작업 후   구현 · 검증 결과 · 되돌리는 법
```

`_template.md` 를 복사해 시작하십시오.

## 규칙

- **근거 데이터는 숫자로.** "많다" 대신 "993편 중 470편(47%)". 센 방법도 함께 적습니다.
- **버린 안을 지우지 마십시오.** 그게 이 문서의 절반입니다.
- **결정을 뒤집으면 새 문서를 만들고 옛 문서에 링크합니다.** 옛 문서를 고쳐 쓰지 않습니다 —
  그때 그 판단이 무엇이었는지가 사라집니다.
- **오너 판단 사항은 임의로 결정하지 않습니다.** 선택지까지 만들어 두고 결정을 받습니다.
