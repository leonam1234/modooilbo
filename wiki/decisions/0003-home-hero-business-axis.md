## 배경

인계서 §3 에 **"히어로 5건이 코드상 종합뉴스 전용(`isGeneralNews` 필터).
`/about` 미션에도 공공데이터 정체성이 없음. 매체 정체성 결정 사안"** 으로 올라 있었다.

발행량의 절반이 사업 축인데 대문 상단에서 구조적으로 빠지는 것이 맞는지가 질문이다.

## 근거 데이터

**사업 축 비중** — 993편 중 470편(47%), 일일 24편 중 12편.

```bash
grep -h '^category:' content/articles/*.md | sort | uniq -c | sort -rn
# 사업 축: grants 82 + industry 80 + labor 79 + startup 78 + deals 77 + bids 74 = 470
# 종합:   society 98 + sports 86 + economy 86 + culture 86 + world 77 + opinion 76 + tech 14 = 523
```

**필터 위치** — [`queries.ts:8`](../../src/lib/queries.ts) 의 `isGeneralNews` 가
`getLeadArticle`(리드) · `getSubLeads`(보조 4건) · `getBreaking`(속보 티커) 세 곳에서
사업 축을 제외한다.

**다만 홈에서 안 보이는 것은 아니다** — [`BizSectionGroup`](../../src/components/BizSectionGroup.tsx)
이 히어로 **바로 아래**, 종합뉴스 6섹션보다 **위에** 사업 카테고리 6개를 전부 실제 카드로
렌더한다('준비 중' 플레이스홀더는 현재 안 쓰이는 경로).

**메타는 이미 기업 데이터 정체성이다** — `HOME_DESCRIPTION`
([`page.tsx:17`](../../src/app/page.tsx))의 첫 문장이 "기업에 필요한 공공데이터 뉴스".

**`/about` 만 비어 있었다** — 미션 본문이 "모두를 위한 신뢰의 뉴스" 일반론뿐.

**방향 근거 문서** — 출고대기 폴더에 묻혀 있던 `2026-07-13_기업데이터뉴스_방향전환/00_회의결론.md`
(현재 `~/GIT/modooilbo-packages/참고문서/`)가 **"종합뉴스 다량 생산에서 벗어나 기업 친화형
데이터 뉴스 채널로 전환한다"** 고 결론. 핵심 독자는 중소기업 대표·소상공인·스타트업·
인사/총무/재무/구매/영업 담당자.

정리하면 **메타·홈 섹션 구조·발행량은 이미 기업 데이터 쪽인데, 대문 톱기사와 `/about`
미션만 종합뉴스 시절 그대로**였다.

## 결정

**D-2.**

**D-3 을 버린 이유** — 코드 주석이 이 배제를 **의도**라고 이미 밝히고 있다.
> "사업 축(정부지원금 등)이 대문 톱기사·속보 티커를 점유해 종합뉴스 톤을 흐리지 않도록"

필터를 통째로 걷어내면 마감 임박 공고가 상시 톱을 차지하고 속보 티커에 공고가 섞인다.
정체성을 선명히 하려다 **속보의 의미를 망가뜨린다.** D-2 는 되돌리기 쉬우니 먼저
운영해 보고, 부족하면 그때 D-3 을 재검토한다.

**D-4 를 버린 이유** — 종합뉴스 매체로서의 첫인상을 사실상 포기하는 변경인데,
7/13 회의 결론도 "종합뉴스를 버린다"가 아니라 "다량 생산에서 벗어난다"였다. 과하다.

**D-1 로 그치지 않은 이유** — 문서만 고치면 화면은 그대로다. 발행의 절반이 대문
상단에서 계속 빠진다.

## 구현

**(a) [`getSubLeads`](../../src/lib/queries.ts) 만 수정.**
`getLeadArticle`·`getBreaking` 의 `isGeneralNews` 필터는 **그대로 뒀다.**

```
count=4 → 사업 축 2 + 종합뉴스 2
한쪽이 모자라면 다른 쪽이 채워 항상 count 를 맞춘다(빈 슬롯 방지)
합친 뒤 byNewest 재정렬 — 축별로 뭉쳐 보이지 않게
```

**`pickVaried()` 를 추가한 이유** — 첫 빌드에서 사업 축 2칸이 **둘 다 공공입찰·둘 다
같은 기자**로 나란히 걸렸다. 하루 24편이 카테고리별 2편씩 **같은 시각(06:59)** 으로
들어오기 때문에 최신순 slice 만 쓰면 자주 재발한다. 서로 다른 축이 안 보이면 보조
4칸을 둔 의미가 없어, 카테고리가 겹치지 않는 것을 먼저 채우게 했다.

**(b) [`/about`](../../src/app/about/page.tsx) 미션에 문단 2개 추가** — 나라장터·정부지원사업·
기업마당·DART 원자료 직접 확인, 금액·마감·자격요건·필요서류 명시, 대상 독자,
그리고 "해당되지 않는 기업과 오해하기 쉬운 조건도 함께 적는다"는 편집 태도.

**하지 않은 것** — 컴포넌트 수정. `HeroLead` 는 `getSubLeads(4)` 를 부르는 유일한
소비처이고 마크업은 그대로다.

## 검증

- `tsc --noEmit` green, 정적 export green(1106페이지)
- 산출 HTML 에서 히어로 구성 확인 — 리드 society(종합), 보조 4칸이
  **공공입찰·정부지원금·경제·스포츠**로 축 2:2 이고 네 칸 모두 다른 카테고리
- 속보 티커에 사업 축 미포함 확인(culture·economy·society·sports)
- 리드가 서브리드에 중복되지 않음
- 렌더 중 `Date.now`/`Math.random` 미사용 — 빌드 타임 캐시와 상대 나이 판정만 씀(불변식)
- `isLead` 전체 1건 불변식 — `getLeadArticle` 미수정이라 영향 없음
- 운영 반영 확인

**확인하지 못한 것** — 이 배치가 실제 클릭·체류에 어떤 영향을 주는지. 측정 지표가
붙어 있지 않아 정성 판단이다. 사업 축 노출이 늘어 종합뉴스 트래픽이 줄 가능성은
배제하지 못했다.

## 되돌리는 법

`getSubLeads` 를 원래의 한 줄 필터로 되돌리고 `pickVaried` 를 지우면 화면이 원상복구된다.
`/about` 문단은 독립적이라 따로 판단할 수 있다.
**D-3 으로 더 나아가려면 이 문서를 고치지 말고 새 결정 문서를 만들 것.**
