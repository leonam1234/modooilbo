# 일일 기사 발행 규약

원고 생산 ↔ `모두일보 개발 및 배포 담당자` ↔ `모두일보 독립 리뷰 담당` 사이의 운영 규약.
2026-08-18 확정, 2026-09-02 승인·배포·색인 인계 흐름 정정, 2026-09-03 병렬 검수 운영 확정.
품질 통과분을 하루 최대 24편까지 인수·검수·발행하면서 실제 사고를 겪고 정리한 규칙이라,
바꾸려면 사유를 남길 것.

## 0. 역할·독립 리뷰·상시 자동 배포 승인 (2026-09-02 정정)

- 개발·발행 역할명은 **`모두일보 개발 및 배포 담당자`**다. 종전 모두일보 총괄·개발담당 업무와 사이트 코딩·유지보수도 이어받는다.
- 패키지는 08:50~08:59 KST에 snapshot을 고정하고 09:00 KST에 검수를 시작한다. `모두일보 독립 리뷰 담당`(Codex 작업 ID `01a05a60-a035-7921-8154-7aa4a7024f31`)은 6편씩 4개 기사 shard를 즉시 병렬 dispatch한다.
- 개발 및 배포 담당자는 같은 09:00 KST에 6편씩 4개 동적 원출처 lane을 병렬 dispatch한다. 독립 리뷰 담당 1명이 하위 결과를 slug별로 합산해 기사별 `reviewedBy`·`reviewedAt`·`reporterInsight`, PASS/HOLD, 수정 요구를 확정한다.
- **유수화님의 2026-09-02 상시 자동 배포 승인을 적용한다.** PASS·HOLD 0이면 별도 승인 질문 없이 CMS 변환, `content/articles/` 반영, Git, 빌드, Preview, Production, 라이브 검증까지 진행한다. HOLD 또는 사용자의 현재 중지 지시가 있으면 멈춘다.
- 검수 뒤 기사 내용이 바뀌면 변경 기사를 독립 리뷰와 최종 게이트에 다시 보내고 다시 PASS·HOLD 0을 확인한다.
- 개발 및 배포 담당자가 Preview·Production·라이브 재검증을 수행하고, 신규 기사
  canonical URL 전건을 `색인 담당자` 작업 `019ef3e0-e684-7be0-a164-3cdfacfeb6fa`로 인계한다.

## 0-A. 09:00 병렬 실행 계약

정확한 4개 리뷰 shard와 4개 동적 lane 배정은 [발행 정본 §1](../09-publishing.md)을 따른다.
24편 기준 각 묶음은 6편이며, 패키지가 24편보다 적으면 실제 기사만 배정하고 숫자를 맞추려고
저품질 기사나 중복 기사를 추가하지 않는다.

1. **08:50~08:59 — snapshot:** 기사 목록, slug, 파일 SHA-256, 이미지 대응, 기존 HOLD를 고정한다.
2. **09:00 — 동시 dispatch:** 독립 리뷰 담당은 R-A~R-D, 개발 및 배포 담당은 D-A~D-D를 한꺼번에 실행·대기열 등록한다. R-A 완료 뒤 R-B를 시작하는 식의 직렬 실행은 금지한다.
3. **결과 즉시 반환:** 각 작업은 묶음 전체를 기다리지 않고 기사 한 편 검수를 끝낼 때마다 아래 행을 반환한다.
4. **단일 합산:** 독립 리뷰 담당 1명만 정본 검수표를 갱신한다. 하위 작업은 원고·이미지·정본 검수표를 직접 수정하지 않는다.
5. **기사별 join:** 개발 및 배포 담당자는 같은 slug의 독립 리뷰 PASS와 동적 게이트 PASS가 모두 있을 때만 `READY`로 올린다.
6. **cohort release:** 현재 release cohort의 모든 기사가 READY이고 HOLD 0이면 별도 승인 질문 없이 자동 배포한다.

```text
slug | reviewShard | reviewedSource | reviewedAtKst | reviewDecision
     | dynamicLane | dynamicSource | dynamicCheckedAtKst | dynamicDecision
     | correctionPending | releaseCohort | finalDecision | notes
```

`reviewDecision`과 `dynamicDecision`의 허용 상태는 `PASS`, `HOLD`, `WAIT_SOURCE_UNTIL=<KST>`다.
`WAIT_SOURCE_UNTIL`은 아직 확인하지 못했다는 뜻이지 PASS가 아니다. 원출처가 10:00에 열리는
채용 기사라면 그 기사만 late micro-lane으로 떼고, 같은 review shard와 dynamic lane의 나머지
기사는 즉시 반환한다. ready 기사들은 첫 cohort로 계속 진행하고 late 기사는 원출처 개시 뒤
독립 리뷰와 동적 게이트를 완료한 후 증분 cohort로 발행한다. **늦은 기사 때문에 ready 기사를
기다리게 하지 않되, 미확인 기사를 ready cohort에 섞지도 않는다.**

결과 충돌은 독립 리뷰 담당이 다수결로 지우지 않는다. 원문 재확인 또는 교정 뒤 변경 기사만
새 snapshot으로 재검수하며, 해결되지 않으면 HOLD다. 독립 리뷰 담당은 기사별 근거를 읽고
최종 PASS/HOLD를 확정해야 하며 하위 작업의 묶음 PASS를 그대로 전재하지 않는다.

## 1. publishedAt

**정본은 실제 게재 시각(KST)이다.** 원고 작성 시각이 아니다.

- 원고에 적힌 시각이 **인수 시점보다 미래**면 빌드가 예약 기사로 분류해 **발행에서 제외**한다.
  → 발행 직전에 실제 발행 시각으로 조정한다.
- 발행이 끝난 뒤 도착한 시각 보정 요청은 **사이트에 반영하지 않는다.**
  이미 게재·색인된 기사의 시각을 사후에 과거로 당기면 기록이 사실과 어긋난다.
  보정 규약은 다음 패키지부터 적용된다.
- 엠바고·예약 발행이 필요한 기사는 인수인계서에 **별도로 명시**한다(그때는 미래 시각이 정상).
- ready·late 증분 cohort마다 `publishedAt`은 실제 배포 직전 KST로 새로 편성한다. 각 기사는
  `reviewedAt`보다 최소 10분 뒤여야 하고 같은 분에는 최대 4편만 둔다. 첫 cohort 시각을 late
  cohort에 소급 복사하지 않는다.

### 사고 이력

- 2026-08-15: 광복절 특집 4편이 미래 시각 탓에 **조용히 누락**됐다. 당시엔 경고가 없어
  발행 건수를 세보고서야 발견했다. → `scripts/build-content.mjs`에 예약 스킵 경고를 신설.
- 8/16·8/17·8/18에도 각 1·4·4편이 미래 시각으로 들어와 경고가 잡아냈다.
  주로 startup·industry 축에서 반복됐다.

## 2. 발행 후 수정

| 유형 | 처리 |
|---|---|
| 사실·수치 오류 | 같은 URL 정정안을 즉시 준비하고 독립 리뷰·최종 게이트 PASS 뒤 상시 승인에 따라 Git·빌드·재배포. 오보 방지가 최우선 |
| 시각·표기 통일 등 형식 | 사이트 미반영, 다음 패키지부터 적용 |

첫 발행 전 검수에서 슬러그에 틀린 사실이 발견되면 슬러그와 이미지 파일명을 함께 고친다.
**한 번 공개한 뒤에는 기존 URL·슬러그를 유지하고 같은 URL에서 정정한다.** 법적 필요 등으로
URL 변경이 불가피하면 독립 리뷰·최종 게이트와 기존 URL의 영구 리디렉션을 함께 준비한다.

## 3. 발행 직전 동적 게이트

인수 문서의 게이트 목록대로 **라이브 원출처를 실제로 열어** 재확인한 뒤 발행한다.
원고 작성과 발행 사이 몇 시간 만에 원출처가 움직이는 일이 실제로 반복됐다.
09:00에는 D-A(공고·접수), D-B(시효·개시), D-C(공시·통계), D-D(기록·정책)를 동시에
dispatch하며, 각 lane은 기사별 결과를 즉시 반환한다. 원출처 개시 전 기사는 lane 전체를
붙잡지 않고 `WAIT_SOURCE_UNTIL` micro-lane으로 분리한다.

### 검증에서 실제로 막아낸 오보

- **8/15 교역조건**: 원고가 `6.9% 하락`이라 썼으나 원출처 표·시계열·첨부 xlsx 원시셀이 전부
  `6.9% 상승`. 한국은행 보도자료의 **서술문 한 줄이 같은 자료의 표와 모순**되는 오기였고
  원고가 그 문장을 승계했다. 지수 레벨(110.59→118.17)로 방향을 확정.
- **8/16 호우**: 05시 예보 기준 원고인데 11시 발표로 갱신되며 제목의 구역·수치가
  현재 예보에 **아예 존재하지 않게** 됐다(raw 대조: '250mm' 0건, '지리산' 0건).
- **8/17 박스오피스**: KOBIS 사후 보정으로 상위 4편 수치가 변동(44명 단위). 명 단위 확정
  수치를 쓴 기사라 그대로 두면 오보.

### 검증 원칙

- **WebFetch 요약 모델은 환각을 낸다.** 숫자·문자열의 존재 여부가 판정을 가르면
  raw 텍스트를 직접 받아 문자열로 세어라. 실제로 요약모델이 원문에 없는 값을 "있다"고 답한 사례가 있다.
- **나라장터**는 SPA·SSO로 웹 화면이 안 열린다. 조달청 공개 API 또는 나라장터 백엔드 JSON으로 우회하고,
  **같은 구간 타 공고에서 취소·변경 차수가 실제로 반환되는지 먼저 확인**(피드 민감도)한 뒤에야
  "차수 없음"을 진짜 음성으로 판정할 수 있다.
- **원출처가 안 열리면 '확인불가'다.** 추측으로 '변경없음'을 내지 않는다.
- **1차 판정은 교차검증에 부친다.** 8/18 PS Plus 건은 1차가 '스토어 미반영'으로 HOLD를 냈으나,
  원출처(블로그)에 수정 이력이 전혀 없음이 확인돼 뒤집혔다 — 미반영은 원출처 변경이 아니라
  롤아웃 진행 중 상태였다. 교차검증이 없었으면 멀쩡한 기사를 하루 묵혔을 것이다.

## 4. 원출처 내부 모순은 임의로 해소하지 않는다

공식 문서끼리 값이 어긋나면 **어느 쪽으로도 단정하지 말고 모순 자체를 독자에게 알린다.**

- 예: KOEN 창업 공고문이 `사업화지원 2026.10~2027.4`와 `최종보고회 2026.6`을 함께 적어
  순서가 성립하지 않았다. 기사는 이를 그대로 서술하고 "주관기관에 확인하라"로 처리했다.
  추정으로 2027년이라 고쳤으면 그게 오보가 된다.
- 기관의 오기를 기사에서 지적하려면 별도 확인 절차가 필요하다. 정확한 수치를 싣는 것만으로
  독자에게 필요한 정보는 전달된다(8/15 교역조건 건에서 한국은행 오기를 지적하지 않은 이유).

## 5. 시효가 있는 기사

당일 행사·마감 임박 건도 **독립 리뷰·최종 게이트 없이 발행하지 않는다.** 게이트 전에 시효가
끝나면 HOLD하거나 종료 사실을 반영한 기록 기사로 다시 써서 독립 리뷰·최종 게이트를 새로 통과한다.

- 2026-08-15: 독립기념관 광복절 행사 기사가 승인 대기 10시간 만에 행사가 종료돼
  예고 기사가 무효화됐다. 과거형 기록 기사로 전면 개고해 발행.
- 날씨·행사·박스오피스처럼 갱신되는 기사는 **기준 시각을 본문에 명시**한다
  ("이 수치는 8월 16일 11시 발표 기준이며 예보는 갱신된다").

## 6. 검산

패키지가 제출한 검산 결과를 **믿지 말고 직접 재실행**한다.

- `FINAL_REGISTRY=1 node 검수/validate-package.mjs` — 레지스트리 반영 후에는 이 모드로 돌려야 한다
  (일반 모드는 "slug already exists"를 정상 동작으로 뱉는다)
- `node 검수/check-recent-duplicates.mjs`
- 태그 대괄호(`tags: [a, b]` YAML 배열 표기) 검사 — `build-content.mjs`가 자동 보정하지만 원본도 고친다
- JPG 규격·1MB·해시중복, 저장소 slug 충돌
- 빌드 후 **발행 건수를 반드시 센다**(예약 스킵 경고와 별개로 이중 확인)

## 7. Preview·Production·라이브 검증·색인 인계

1. 독립 리뷰와 최종 게이트가 PASS·HOLD 0이면 상시 자동 배포 승인에 따라 CMS 변환·코드 게이트·빌드를 마치고 비-master 릴리스 브랜치에 커밋한다.
2. Preview에서 `/`·`/policy/`·`/newsroom/`과 신규 기사 경로 전건을 엔진·뷰포트 4조합으로
   검사한다. 24편이면 총 27경로다. 비교 이미지와 660px 원본도 눈으로 확인한다.
3. 스모크의 자동 PASS는 HTTP 상태·canonical·index/follow·OG·이미지를 보증하지 않는다.
   이 항목을 별도 전수 확인한 뒤 검증한 SHA만 `master`에 push하고 원격 SHA를 대조한다.
4. HEAD·`origin/master`·원격 `master`가 Preview 검증 SHA와 모두 같음을 재확인한다. 같은 릴리스
   worktree에서는 통제된 `--force-branch`, clean master에서는 일반 명령으로 Production 배포하고
   신규 기사 URL의 HTTP·canonical·index/follow·OG를 각 1회만 라이브 확인한다. 브라우저 4환경과
   사이트맵·자산 전수검사는 Preview에서 끝내며 운영 도메인에 반복하지 않는다.
5. HTTP 200·self-canonical·index/follow를 확인한 신규 기사 canonical URL 전건을 색인 담당자에게
   발행일·건수·사이트 커밋·IndexNow 결과와 함께 보낸다. `handoff_sent`·`requested`·
   `submitted`·`indexed_current`는 서로 다른 상태다.

병렬 운영 변경은 추적·보안 구현을 변경할 권한이 아니다. 공개 페이지 GA4
`G-R2MDE3WDFY`는 `<head>`의 조건 없는 구글 표준 직접 스니펫 1개를 유지하고, 인증 토큰
경로 4종은 Pages middleware에서 GA4·AdSense·Cloudflare 태그와 Flight 복제 노드를 제거한다.
AdSense 실제 스크립트는 React hydration 뒤 `afterInteractive`로 1회 로드한다. 이 세 불변식을
건드리는 별도 변경은 `docs/tracking.md`와 `npm run test:analytics` 회귀 검증 없이는 배포하지 않는다.

## 8. 종료되는 사안은 `eventEndsAt`을 적는다

전시·공연·상영·마감·모집처럼 **기간이 끝나는 기사**는 frontmatter에 종료 시각을 명시한다.

```
eventEndsAt: 2026-08-27 18:00
```

그 시각이 지나면 기사 상단에 자동으로 종료 안내가 붙는다(`components/EventEndedNotice.tsx`).
**기사 본문은 고치지 않는다** — 뉴스는 발행 시점의 기록이므로 사후에 다시 쓰지 않고
"지금은 끝났다"는 사실만 덧붙인다.

### 왜 필요한가

기간이 끝나도 검색 노출은 남는다. 2026-08-18 네이버 실측에서 국립중앙박물관 여름
연장운영 기사가 **노출 36,703회**(사이트 전체 노출의 약 절반)를 유지한 채 내용은
전날 만료된 상태였다. CTR 0.1%로 클릭은 거의 없었지만, 들어온 독자는 끝난 시간표를
보게 된다. 전수 조사 결과 920편 중 195편(21%)이 같은 상태였다.

### 적는 기준

- **적는다**: 마감·접수·모집이 있는 공고, 기간이 정해진 전시·공연·상영·행사
- **적지 않는다**: 통계·지표 발표, 경기 결과, 공시, 계약·합병, 법령 해설처럼
  기간 개념이 없는 기사. 여기에 종료 안내가 붙으면 오히려 틀린 표시가 된다.
- 시각을 모르면 종료일 `23:59`로 둔다(그 날까지는 유효하므로).

### 자동 추정 금지

제목의 날짜를 기계적으로 파싱해 종료일을 추정하면 안 된다. "7월 ICT 수출 533.6억달러"
같은 기사에 만료 딱지가 붙는다. 2026-08-18 소급 적용 때도 마감·모집·상영 등
**기간 종료가 제목에 분명한 87건만** 골랐고, 통계·결과·공시 83건은 정규식으로 제외했다.

### 상태 정보가 바뀐 기사는 갱신한다

관람시간·운영시간처럼 **끝나는 게 아니라 바뀌는** 정보는 종료 안내가 아니라 갱신 대상이다.
`updatedAt`을 추가하고 본문 상단에 갱신 블록을 넣되, 원문은 아래에 보존한다
(국립중앙박물관 기사가 이 방식으로 처리됐다). `eventEndsAt`이 붙은 기사에 `updatedAt`이
생기면 종료 안내는 자동으로 제외된다 — 현재 정보를 담은 기사에 만료 표시가 붙으면 안 된다.
