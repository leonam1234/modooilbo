# 05 · 직접취재 실무 매뉴얼

> **이 문서는 사람이 읽고 그대로 실행하는 정본입니다.** AI가 대신할 수 없는 일만 담았습니다.
> 담당자가 바뀌어도 이 문서만 읽으면 첫날부터 일할 수 있게 썼습니다.
> 최초 작성 2026-08-28.

---

## 1. 왜 이 일을 하는가

모두일보는 하루 24편을 냅니다. 그런데 그중 **자체 취재(direct)가 사실상 0편**입니다.

```
8/21  25.0%  ← direct 6편
8/22  13.0%  ← direct 3편
8/23~8/25  0%
8/26   4.0%  ← direct 1편 (서면 인터뷰)
8/27~8/28  0%

7일 이동 평균  2.4%   (목표 20~30%)
```

이 숫자가 왜 중요한가 — **포털(네이버·다음) 제휴 심사에서 자체기사 비율이 핵심 지표**입니다.
공개 자료를 잘 정리한 기사(desk)만 아무리 많아도 "직접 취재하는 언론"으로 인정받지 못합니다.

**목표는 하루 24편 중 5~7편이 direct입니다.** 그래야 20%가 됩니다.

---

## 2. 무엇이 direct이고 무엇이 아닌가

이걸 틀리면 **비율을 높이려다 매체 신뢰를 잃습니다.** 심사에서 분류를 뒤집어 보면 바로 드러납니다.

### direct — 자체 취재

| 유형 | `reportingType` | 조건 |
|---|---|---|
| 기관·기업에 질의하고 **답을 받음** | `inquiry` | 회신이 실제로 와야 함 |
| 사람을 만나거나 서면 인터뷰 | `interview` | 답변자 동의 필요(§6) |
| 공개 데이터를 **직접 집계·비교·검산** | `data-analysis` | 독립된 데이터셋 2개 이상 + 재현 가능한 산식 |
| 현장에 가서 확인 | `field` | |
| 기존 보도의 후속을 직접 확인 | `follow-up` | |

### direct가 아닌 것 — 전부 desk

- 질의를 **보내기만 하고 회신을 못 받은** 경우
- 보도자료·공고를 잘 읽고 정리한 것 (아무리 공들여도 desk)
- 하나의 원문 안에 있는 수치를 더하거나 백분율로 바꾼 것
- 여러 기사를 종합한 것

> ⚠️ **애매하면 desk로 적으십시오.** 지금까지 코덱스가 과대 분류를 거부해 온 것은
> 옳은 판단이었습니다. 분류를 느슨하게 하면 지표만 좋아 보이고 심사에서 더 크게 다칩니다.

---

## 3. 하루 흐름 — 전날 저녁에 씨를 뿌린다

**핵심 원리: 오늘 질의를 보내면 오늘 기사에는 못 씁니다.** 회신이 늦게 오기 때문입니다.
그래서 **전날 보내고 다음날 받아 씁니다.**

```
D-1 저녁   질의 5~8건 발송          ← 담당자의 실제 업무는 여기가 90%
D   오전   회신 도착분 확인 → 코덱스에 전달
D   낮     회신 온 것만 direct 기사로 작성
```

회신율은 50~70% 정도로 잡으십시오. **5편의 direct가 필요하면 8건을 보냅니다.**

---

## 4. 무엇을 물을 것인가 — 질문은 이미 널려 있습니다

새로 발굴할 필요가 없습니다. **매일 게이트에서 걸리는 것들이 곧 질문입니다.**

### (A) 게이트가 잡아낸 충돌 — 최우선

발행 직전 검증에서 "두 공식 문서가 다르다"고 걸린 건들입니다. 이건 **기관에 물어야만
풀리는 질문**이고, 물으면 그 자체로 direct가 됩니다.

지금 `modooilbo-packages/출고대기/보류자료/`에 **9건이 답을 기다리고 있습니다.**

| 원고 | 물어야 할 것 |
|---|---|
| `2026-08-27-seoul-fintech-week-…` | 필수서류 4번이 첨부 공고문(4대 사회보험 명부)과 포털 본문(법인등기부등본)에서 다릅니다. 어느 쪽이 맞습니까 |
| `2026-08-27-hwaseong-…` | 나라장터는 전자제출·9/8 개찰, 공고문은 방문제출·평가 후 개찰입니다. 실제 절차는 무엇입니까 |
| `2026-08-27-kopri-…` | 접수 엔진 점검이 끝났습니까. 현재 서류·마감 기준을 확인해 주십시오 |
| `2026-08-27-summer-messiah-…` | 상세 페이지 관람시간 120분과 예매 API 19:30~23:00가 다릅니다. 실제 종료 시각은 언제입니까 |
| `2026-08-26-kim-changwan-band-…` | 러닝타임 표기가 120분과 70분으로 충돌합니다 |

**이 5건만 물어도 direct 5편입니다.** 게다가 죽어 있던 원고가 살아납니다.

### (B) 코덱스가 매일 뽑아주는 질의 후보

패키지마다 `직접취재_질의후보_3-5건.md`가 들어옵니다. 기관·부서·질문·문의 창구·근거 URL이
이미 정리돼 있으니 **그대로 발송만 하면 됩니다.**

### (C) 좋은 질문의 조건

- **공개 자료를 읽으면 알 수 있는 것은 묻지 않습니다.** 그건 desk입니다.
- **독자의 행동을 바꾸는 것**을 묻습니다. 마감·자격·금액·필요서류·절차.
- **답이 예/아니오로 끝나지 않게** 묻습니다. "확인해 주십시오"보다 "어느 쪽이 맞습니까".
- 한 번에 **2~3개**만 묻습니다. 많으면 회신율이 떨어집니다.

## 5. 질의 메일 — 그대로 쓰는 서식

### 5-1. 발송 계정 문제 (먼저 읽으십시오)

⚠️ **현재 `newsroom@modooilbo.com`으로 메일을 보낼 수 없습니다.** 수신 포워딩만 됩니다.
이 설정이 열리기 전까지는 아래 둘 중 하나인데, **둘 다 문제가 있습니다.**

| 방법 | 문제 |
|---|---|
| 개인·타사 계정으로 발송 | 기관이 "모두일보 취재"로 인정하지 않을 수 있음. 회신율이 크게 떨어짐 |
| 관계사(브리찌 등) 계정 | 기사마다 **이해관계 고지**를 달아야 함(§6). 2026-08-26 현성전자 건이 이 경우 |

**따라서 이 업무의 첫 번째 과제는 발송 계정을 여는 것입니다.**
ImprovMX SMTP 릴레이(저렴·빠름) 또는 Google Workspace(안정적·유료). 오너 결정 사항입니다.

### 5-2. 제목

```
[모두일보 취재문의] {기관명} {사업·공고명} 관련 확인 요청
```

### 5-3. 본문 서식

```
안녕하십니까.
인터넷신문 모두일보(등록번호 경기 아54891) {담당자명}입니다.

{기관명}이 {날짜} 공고한 「{공고명}」을 기사로 다루려 합니다.
독자에게 정확히 전달하기 위해 아래 사항을 확인 부탁드립니다.

1. {질문}
2. {질문}

기사에는 회신 내용을 인용할 수 있습니다.
인용을 원하지 않으시면 그 부분을 알려주시면 배경 설명으로만 쓰겠습니다.
담당자 성함·직책을 함께 알려주시면 기사에 표기하겠습니다.
익명을 원하시면 「{기관명} 관계자」로 적겠습니다.

가능하시면 {날짜} 오후까지 회신 부탁드립니다.
공고 원문: {URL}

감사합니다.

모두일보 {담당자명}
{연락처} / newsroom@modooilbo.com
```

**왜 이렇게 쓰는가**
- 등록번호를 밝히면 정식 언론사 문의임이 드러나 회신율이 오릅니다.
- **인용 동의와 실명 표기 여부를 먼저 물어야** 나중에 문제가 없습니다. 8/26 현성전자
  건에서 이 확인이 없어 발행이 하루 늦어졌습니다.
- 회신 기한을 적어야 실제로 답이 옵니다.

### 5-4. 전화로 받은 경우

전화 취재도 direct(`interview`)입니다. 다만 **통화 직후 메모를 남기고**, 가능하면
"방금 말씀하신 내용을 메일로 한 줄 주시겠습니까"라고 요청해 서면 근거를 남기십시오.
근거 없는 「○○에 확인한 결과」는 쓰지 않습니다.

## 6. 이해관계 — 반드시 지킬 것

관계사·거래처를 다룰 때는 **대가를 안 받았어도** 관계를 공개합니다.

```
광고·협찬을 받았다      → sponsor 필드를 달고 광고 표시. reporting: sponsored
                          (direct 비율에는 안 잡힙니다)
대가 없이 취재만 했다   → reporting: direct + 기사 하단 「취재·이해관계 안내」
```

기사 하단 서식 (2026-08-26 현성전자 건에서 실제 사용):

> 이 기사는 {회사}의 서면 인터뷰와 공개 자료를 바탕으로 작성한 직접취재 기사다.
> {관계 설명}. 모두일보는 이번 기사 게재와 관련해 {회사}로부터 광고비 또는 별도
> 대가를 받지 않았다.

⚠️ **관계사 기사를 고지 없이 내면 포털 심사에서 자체기사 비율보다 훨씬 크게 다칩니다.**
비율을 올리려고 관계사 기사를 늘리는 것은 자충수입니다.

---

## 7. 회신을 받은 뒤 — 코덱스에 넘기는 형식

회신이 오면 **원문을 그대로** 아래 형식으로 정리해 코덱스에 전달합니다.
가공하지 마십시오. 요약도 코덱스가 합니다.

```markdown
# {기사 주제} 서면 취재 증빙

- 질문 발송: 2026-0X-XX HH:MM KST
- 답변 수신: 2026-0X-XX HH:MM KST
- 방식: 이메일 서면 / 전화
- 발송 계정: {계정}
- 답변자: {성함} {직책}   (익명 요청 시 「{기관명} 관계자」)
- 인용 동의: 있음 / 없음(배경 설명만)
- 이해관계: 없음 / {관계 설명}

## 보낸 질문
1.
2.

## 받은 답변 (원문 그대로)
{붙여넣기}

## 답변에 없는 것
{물었으나 답이 없는 항목. 기사에 쓰면 안 되는 것들}
```

**「답변에 없는 것」을 반드시 적으십시오.** 이게 없으면 코덱스가 답변에 없는 내용을
추측으로 채울 위험이 있습니다.

---

## 8. 하지 말 것

- **회신 없는 질의를 direct로 올리지 마십시오.** 보낸 것만으로는 desk입니다.
- **답변에 없는 수치·성과를 만들지 마십시오.** 8/26 건에서 판매 순위·판매량 주장이
  답변에 없어 전부 제외했습니다. 그게 맞는 처리입니다.
- **인용 동의 없이 실명을 쓰지 마십시오.** 실명이 나가는 건 실제 개인입니다.
- **과거 기사에 reporting을 소급 추정하지 마십시오.** 없으면 그냥 `unknown`입니다.

---

## 9. 첫 주 할 일

1. **발송 계정을 여십시오.** 이게 안 되면 나머지가 다 반쪽입니다(§5-1).
2. 보류자료 9건 중 **답을 기다리는 5건**부터 질의를 보내십시오(§4-A).
   죽어 있던 원고가 살아나고 direct도 채워집니다.
3. 매일 저녁 코덱스의 `직접취재_질의후보`를 확인해 **8건 발송**을 습관으로 만드십시오.
4. 회신은 §7 형식으로 정리해 다음날 오전 코덱스에 넘기십시오.

집계 확인:

```bash
cd ~/GIT/modooilbo && node scripts/reporting-report.mjs
```
