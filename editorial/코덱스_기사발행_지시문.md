## 기사 = 파일 1개
`content/articles/<슬러그>.md` 로 **1기사 1파일**. 슬러그 = 영문 소문자·숫자·하이픈, **날짜 접두사로 고유하게**(예: `2026-06-30-budget-clash`).

복사용 형식은 **`content/article-quality-template.md` 한 파일만 정본**으로 사용한다. 별도 축약
예제를 복사하지 않는다. 2026-09-01 이후 신규 일반 기사는 `reporting`·`verificationNote`·
`addedValue`·`sourceBasis`·`visualType`·`aiRole`과 독립 리뷰 뒤 입력되는 `reviewedBy`·
`reviewedAt`·`reporterInsight`가 필요하다.

카테고리(영문 슬러그만): `economy` `society` `world` `culture` `sports` `opinion`,
`grants` `bids` `startup` `industry` `labor` `deals`, 그리고 기존 URL 호환용 `tech`.
`tech`는 유효하지만 신규 일일 편성은 동결한다. **`politics`는 유효 카테고리가 아니다.**
- 이미지는 비워도 됨(카테고리 맞는 무료 스톡 자동). 특정 이미지가 있으면 `image:` 에 URL.

## 발행 흐름
1. 08:50~08:59 KST에 콘텐츠 패키지의 수량·slug·검수문서·HOLD·이미지 대응과 파일 해시 snapshot을 고정한다.
2. **09:00 KST에 즉시 병렬화한다.** `모두일보 독립 리뷰 담당`(Codex 작업 ID `01a05a60-a035-7921-8154-7aa4a7024f31`)은 24편을 6편씩 R-A~R-D 네 article shard로 동시에 dispatch한다. 개발 및 배포 담당자는 같은 시각 D-A~D-D 네 동적 원출처 lane을 동시에 dispatch한다. 정확한 배정은 `wiki/09-publishing.md` §1을 따른다.
3. 리뷰 shard는 기사별 원출처·확인시각·대조값·PASS/HOLD·수정 요구만 반환하고 원고나 정본 검수표를 수정하지 않는다. 독립 리뷰 담당 1명이 slug별 근거를 읽고 `reviewedBy`·`reviewedAt`·`reporterInsight`와 최종 PASS/HOLD를 합산한다.
4. 동적 lane은 묶음 완료를 기다리지 않고 기사별 결과를 즉시 반환한다. 늦게 열리는 지원·접수·예매 화면은 그 기사만 `WAIT_SOURCE_UNTIL=<KST>` micro-lane으로 분리하고 나머지 ready 기사는 계속 진행한다.
5. 같은 slug의 독립 리뷰 PASS와 동적 게이트 PASS가 모두 있고 수정 대기가 없을 때만 현재 release cohort의 `READY`로 확정한다. `WAIT_SOURCE_UNTIL`은 PASS가 아니므로 해당 cohort에서 제외한다.
6. 수정 기사는 새 snapshot으로 독립 리뷰와 최종 동적 게이트에 다시 보내고 다시 PASS·HOLD 0을 확인한다.
7. HOLD가 하나라도 있으면 자동 배포를 멈추고 해당 기사 교정·재검수를 우선한다. `WAIT_SOURCE_UNTIL`만 late cohort로 분리할 수 있으며, 미확인 기사를 PASS로 바꾸거나 HOLD를 범위에서 임의 제외하지 않는다.
8. current release cohort 전건이 PASS·HOLD 0이면 **2026-09-02 상시 자동 배포 승인**에 따라 별도 승인 질문·대기 없이 CMS 변환 → 정적·편집 게이트·빌드 → 생성물 포함 Git 커밋 → Preview → Production → 라이브 검증을 수행한다.
9. 늦은 원출처 기사는 개시 뒤 micro-lane 재확인과 독립 리뷰 합산을 완료해 PASS·HOLD 0인 별도 증분 cohort로 자동 배포한다. 첫 cohort의 `publishedAt`을 소급 복사하지 않는다.
10. 운영 라이브 검증 뒤 신규 기사 canonical URL 전건을 HTTP 200·self-canonical·index/follow 확인 후 `색인 담당자`(작업 ID `019ef3e0-e684-7be0-a164-3cdfacfeb6fa`)에게 발행일·건수·사이트 커밋·IndexNow 결과와 함께 보낸다.
11. `handoff_sent`·`requested`·`submitted`·`indexed_current`를 서로 다른 상태로 기록한다.

## 병렬화가 바꾸지 않는 불변식

- 공개 페이지 GA4 `G-R2MDE3WDFY`는 `<head>`의 조건 없는 구글 표준 직접 스니펫 1개를 유지한다. 동의·시간 게이트나 `afterInteractive`로 바꾸지 않는다.
- 인증 토큰 경로 4종은 Pages middleware가 GA4·AdSense·Cloudflare 태그와 Flight 복제 노드를 제거하는 이중 방어를 유지한다.
- AdSense 실제 스크립트는 React hydration 뒤 `afterInteractive`로 1회 로드한다. raw async head 실행으로 되돌리지 않는다.
- 위 구현을 별도 변경해야 하면 `docs/tracking.md`를 먼저 읽고 `npm run test:analytics`를 통과시킨다.
