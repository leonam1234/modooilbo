# 제작방식 정본 - 모두일보 콘텐츠 생산

최종 갱신: 2026-09-05 KST

## 핵심 정의

모두일보는 사이트 개발 프로젝트가 아니라 콘텐츠 생산 프로젝트다.

생산 대상은 다음과 같다.

- 기사 원고
- 기사 썸네일/삽화/카드뉴스 이미지
- 유튜브/쇼츠 영상 기획안, 대본, 자막 문안
- 카테고리별 톤앤매너와 편집 기준

## 표준 작업 흐름

1. 주제 접수
2. 카테고리 분류
3. 리스크 등급 판단
4. 출처 확인
5. 취재·검증 행위와 원자료 대비 추가 가치 기록
6. 기사 구조 설계
7. 초안 작성
8. 사실확인 및 표현 검수
9. 이미지/영상 출처와 AI 역할 기록
10. 원고·이미지·공식 근거·HOLD·미확인 사항을 출고대기 패키지에 정리
11. 08:50~08:59 KST에 `모두일보 개발 및 배포 담당자`가 패키지 snapshot과 1차 정적 게이트 수행
12. 09:00 KST에 독립 리뷰 담당이 6편 × 4개 기사 shard, 개발 및 배포 담당자가 6편 × 4개 동적 원출처 lane을 즉시 병렬 dispatch
13. `모두일보 독립 리뷰 담당`(작업 ID `01a05a60-a035-7921-8154-7aa4a7024f31`) 1명이 하위 결과를 기사별로 합산하고 PASS/HOLD·검수 필드 확정
14. 개발 및 배포 담당자가 slug별 리뷰 PASS와 동적 PASS를 결합해 READY 후보를 만들고 수정분 재검수·최종 게이트 수행
15. 독립 리뷰 PASS, 동적·최종 게이트 PASS, 필수 사람 검수 필드 완성을 충족한 각 기사는 **기사별 상시 자동 배포 승인**에 따라 별도 승인 질문 없이 즉시 CMS 변환·게이트·빌드·Git 커밋·Preview 검증·Production 배포·라이브 검증 수행
16. HOLD·`WAIT_SOURCE_UNTIL`·엠바고·미래 `publishedAt`·기사별 검증·빌드·Preview 실패는 해당 기사만 release에서 제외하고, 조건부 PASS는 동적 재확인 뒤 PASS로 승격될 때 13~15단계 수행
17. 라이브 검증된 신규 기사 canonical URL 전건을 `색인 담당자`
    (작업 ID `019ef3e0-e684-7be0-a164-3cdfacfeb6fa`)에게 인계

콘텐츠 생산 담당은 1~10까지만 수행한다. `reviewedBy`·`reviewedAt`·`reporterInsight`를
초안 단계에서 임의로 채우지 않고, 승인·배포·색인 상태를 대신 확정하지 않는다.

## 09:00 병렬 검수 원칙

- 24편은 6편씩 4개 article shard로 나누며 각 shard에 6명 기자의 기사 1편씩을 배정한다.
  정확한 R-A~R-D 배정표는 `wiki/09-publishing.md` §1이 정본이다.
- 발행 직전 원출처 재확인은 D-A 공고·접수, D-B 시효·개시, D-C 공시·통계,
  D-D 기록·정책 4개 lane으로 나눠 같은 09:00 KST에 시작한다.
- 하위 검수 작업은 read-only로 기사별 근거·판정만 반환한다. 독립 리뷰 담당 1명만 정본 검수표와
  `reviewedBy`·`reviewedAt`·`reporterInsight`를 확정한다.
- 늦게 열리는 지원·접수·예매 화면은 해당 기사만 `WAIT_SOURCE_UNTIL=<KST>`로 떼어 낸다.
  미확인 기사를 PASS로 만들지 않으며, 이미 두 게이트를 통과한 ready 기사도 함께 기다리게 하지 않는다.
- 기사별 독립 리뷰와 동적·최종 게이트가 PASS이고 필수 사람 검수 필드가 완성되면 상시 자동 배포
  승인에 따라 별도 승인 질문 없이 즉시 배포한다. HOLD·WAIT_SOURCE·시간 제한·기사별 실패는 해당
  기사만 제외하고 READY 기사는 기다리지 않는다. 조건부 PASS는 재확인 뒤 PASS로 승격될 때 낸다.
  사용자의 현재 중지·보류 지시는 우선한다.

## 8.5점 목표의 출고 원칙

- 공식 기준은 `docs/editorial-quality-as-is-to-be.md`, 코드 게이트는 `scripts/lib/editorial-quality.mjs`다.
- 2026-09-01 이후 신규 기사는 100점 중 80점 미만이면 출고하지 않고, 이동평균 85점 이상을 유지한다.
- 하루 24편은 의무량이 아니다. 확인 행위나 독자 가치가 약하면 기사 수를 줄인다.
- `direct`는 사람이 직접 질의·인터뷰·현장 확인했거나 편집국이 독자 계산·분석을 수행한 경우다.
- 보도자료와 공개문서를 읽고 재구성한 기사는 `desk`다. 문장이 독창적이라는 이유만으로 `direct`가 되지 않는다.
- 취재 방식과 AI 활용은 별도로 기록한다. AI 사용 사실은 직접취재를 무효화하지 않고, AI 미사용 사실은 직접취재의 증거가 되지 않는다.
- 공개자료 기사도 배포 전 기자 실명과 검수시각을 남긴다. 기자는 원문을 다시 열어 수치·기한·자격을 대조한다.
- 개인적인 생각은 감상문으로 섞지 않는다. `reporterInsight`에서 원문 근거, 독자 영향, 기자 판단을 분리해 쓴다.

## 실시간 키워드 기반 제작 흐름

판다랭크, 네이버, 구글 등에서 확인한 인기 검색어는 기사 아이디어의 출발점으로 사용한다.

1. 인기 키워드 확인
2. 기사화 가능 여부 판단
3. 정치/법률/의료/금융/범죄/사고/평판 리스크 확인
4. 원출처와 2차 출처 분리
5. 후킹 제목 후보 작성
6. 기사 구조 작성
7. 사실확인 후 출고대기 정리

벤치마킹은 주제, 제목 구조, 독자 반응 포인트까지만 참고한다. 기존 기사 문장, 구성, 독점 취재 내용은 베끼지 않는다.

## 헤드라인 기준

- 독자가 궁금해할 질문형 제목은 사용할 수 있다.
- 사실보다 앞서가는 단정형 제목은 피한다.
- 특정 집단을 조롱하거나 혐오를 유도하는 표현은 피한다.
- 정치적 사안은 중립형 제목과 쟁점형 제목을 함께 검토한다.
- 내부에서는 "어그로"라고 부를 수 있으나, 운영 문서와 외부 명칭은 "트렌드/헤드라인 편집"으로 둔다.

## 리스크 등급

### 낮음

- 행사 안내
- 제품/서비스 소개
- 생활 팁
- 일반 정보성 글

처리: 내부 자료가 충분하면 작성 가능. 그래도 출처와 기준일을 남긴다.

### 중간

- 기업 비교
- 시장 동향
- 정책 변화
- 가격, 혜택, 성능 비교

처리: 최신성 확인 필요. 최소 1개 이상의 신뢰 가능한 출처를 표시한다.

### 높음

- 정치, 법률, 의료, 금융, 범죄, 사고
- 개인/기업 평판
- 분쟁, 의혹, 폭로성 내용

처리: 사용자 승인 전 단정 표현 금지. 필요하면 출처 2개 이상 확인 후 작성한다.

## 카테고리별 톤앤매너

카테고리별 담당자는 같은 기사 구조를 쓰더라도 문체와 우선순위를 다르게 가져간다. 총괄은 최종 검수와 출고 통제를 맡고, 실제 초안은 카테고리 담당자 톤으로 작성한다.

### 트렌드/헤드라인

- 검색어에서 독자가 궁금해할 쟁점 문장을 뽑는다.
- 제목 후보는 질문형, 비교형, 반전형을 섞어 만든다.
- 클릭 유도는 허용하지만 허위, 과장, 조롱, 혐오는 금지한다.

### 사회/생활

- 짧고 명확하게 쓴다.
- 독자가 바로 이해할 수 있는 절차와 영향을 먼저 말한다.
- 불안 조장 표현을 피한다.

### 경제/비즈니스

- 숫자, 기준일, 비교 조건을 분명히 쓴다.
- 기업 홍보문처럼 보이지 않게 사실과 해석을 분리한다.
- "가능성", "전망", "확인 필요"를 구분한다.

### IT/AI/테크

- 기술 용어를 쉬운 말로 풀어쓴다.
- 작동 방식, 기대효과, 한계를 같이 적는다.
- 과장된 혁신 표현을 남발하지 않는다.

### 문화/연예

- 가볍게 쓰되 루머성 표현을 피한다.
- 팬덤, 인물 평판, 사생활 관련 내용은 고위험으로 본다.

### 지역/행사

- 언제, 어디서, 누가, 무엇을, 왜, 어떻게를 우선한다.
- 방문자에게 필요한 정보와 이동/참여 조건을 먼저 둔다.

## 이미지 제작 기준

- 기사 내용을 보조하는 이미지로 만든다.
- 실제 인물, 기업 로고, 장소를 임의로 합성하지 않는다.
- 특정 사건 보도에서 실제 사진처럼 오해될 수 있는 AI 이미지는 피하거나 "AI 생성 이미지" 표기를 남긴다.
- 썸네일 문구는 기사 제목을 그대로 반복하지 말고 핵심 질문 또는 핵심 숫자를 강조한다.
- 기사 대표 이미지는 1200 x 675 px, 16:9, 300KB 이하를 권장한다.
- 카드와 홈 화면에서 중앙 기준으로 크롭되므로 핵심 피사체는 가운데에 둔다.
- 정치·사건·범죄·사고 등 고위험 기사에서는 실사풍보다 현대미술형 에디토리얼 일러스트를 우선한다.

## 영상 제작 기준

- 영상은 기사 요약형, 설명형, 쇼츠형으로 나눈다.
- 쇼츠는 첫 3초에 질문 또는 핵심 상황을 둔다.
- 유튜브 긴 영상은 배경 설명, 근거, 결론 순서로 구성한다.
- 자막만 봐도 이해되도록 쓴다.

## 발행 전 체크리스트

- 제목이 사실보다 과장되지 않았는가
- 출처와 기준일이 있는가
- 실제 취재·대조·계산 행위를 `verificationNote`로 재현할 수 있는가
- 원자료에 더한 독자 가치가 `addedValue`에 구체적으로 적혔는가
- `reporting`·`sourceBasis`·`visualType`·`aiRole`이 사실과 일치하는가
- 편집 품질 80점과 같은 분 최대 4편 규칙을 통과하는가
- 검수 기자 실명과 검수 완료시각이 있고 배포 전 시각인가
- 기자 해설이 원문 요약을 반복하지 않고 독자에게 판단 근거를 주는가
- 개인/기업을 부당하게 비난하지 않는가
- 저작권 있는 원문을 베끼지 않았는가
- 이미지가 실제 자료처럼 오해되지 않는가
- 출고대기 패키지가 개발 1차 게이트 전에 완성됐는가
- 독립 리뷰 전용 필드를 생성 담당자가 임의로 채우지 않았는가
- 09:00에 독립 리뷰 4개 shard와 동적 원출처 4개 lane을 직렬 대기 없이 dispatch했는가
- 독립 리뷰 담당 1명이 기사별 근거와 PASS/HOLD를 합산했는가
- `WAIT_SOURCE_UNTIL` 기사를 ready cohort에서 제외하고 late cohort로 분리했는가
- CMS·Git·빌드·발행·배포는 기사별 독립 리뷰와 동적·최종 게이트 PASS 및 필수 사람 검수 필드
  완성 뒤 즉시 진행되고, HOLD·WAIT_SOURCE·시간 제한·기사별 실패만 제외되는가
- 라이브 검증 뒤 신규 기사 canonical URL 전건을 색인 담당자에게 인계했는가
